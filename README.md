# Date, not Hate

PWA для пар: предлагайте свидания без упрёков, распределяйте подготовку и сохраняйте добрые воспоминания.

## Быстрый старт

```bash
docker compose up -d
npm install
npm run dev
```

Команда `npm run dev` перед запуском корректно завершает старые процессы API на `3001` и Vite на `5173`, затем запускает оба заново. Если в консоли Vite появляется `http proxy error: /api/...`, API не запущен: используйте именно команду выше. Перед этим Docker Desktop должен быть запущен. После изменения backend-кода перезапустите `npm run dev`.

Откройте `http://localhost:5173`. Этот режим предназначен только для разработки на компьютере.

Переменные backend: `DATABASE_URL=postgres://date_not_hate:date_not_hate@localhost:5432/date_not_hate`, `PORT=3001`, `FRONTEND_ORIGIN=http://localhost:5173`.

## Публичный сервер и домен

Для обычного использования на телефонах нужен VPS с публичным IPv4 и собственный домен. На сервере приложение работает в Docker, а Caddy автоматически выпускает доверенный HTTPS-сертификат Let’s Encrypt. Это даёт работающие PWA, Push, magic-link и ссылки в письмах.

Точная инструкция для `do.date-not-hate.ru` и VPS `212.118.41.67` находится в [DEPLOYMENT.md](DEPLOYMENT.md).

1. Купите домен и VPS с Ubuntu 22.04+ или аналогичной Linux-системой. В DNS у регистратора добавьте `A`-запись для выбранного поддомена, например `dates.example.com`, на публичный IPv4 VPS. Откройте на VPS входящие порты `80/tcp` и `443/tcp`.
2. Скопируйте проект на сервер, установите Docker Engine и Docker Compose Plugin. В каталоге проекта создайте `.env` из шаблона:

```bash
cp .env.production.example .env
npm install
npm run push:keys -w backend
```

3. Откройте `.env`: укажите свой домен в `APP_HOST`, `APP_URL` и адрес для сертификатов в `ACME_EMAIL`; задайте новые длинные значения `POSTGRES_PASSWORD` и `JWT_SECRET`; вставьте ключи `VAPID_*` из предыдущей команды.
4. Настройте Unisender Go по разделу ниже, укажите подтверждённый `MAIL_FROM` и `UNISENDER_GO_API_KEY` в `.env`.
5. Запустите сервис:

```bash
docker compose -f docker-compose.prod.yml up --build -d
docker compose -f docker-compose.prod.yml logs -f caddy
```

После выдачи сертификата откройте `https://<ваш-домен>` на каждом телефоне, выберите «Добавить на экран Домой» и включите Push в разделе «Мы». Для обновления приложения на сервере используйте `docker compose -f docker-compose.prod.yml up --build -d`.

## Что уже входит в MVP

- регистрация, подтверждение email и вход по паролю; вход сразу открывает уже созданное пространство;
- восстановление пароля по одноразовой magic-link, действующей 30 минут;
- создание пространства и email-приглашение партнёра с ролью, заданной администратором;
- настройка доступных типов свиданий в разделе «Мы»: администратор может включать, отключать и добавлять варианты;
- подсказки по подготовке внутри типов свиданий;
- календарная лента, история, до трёх фото, email-уведомления, Push и обновление уведомлений в приложении каждые 30 секунд;
- при создании свидания оба партнёра получают письмо с `.ics`-вложением для ручного добавления события в календарь;
- выдача события и напоминания о подготовке за 7 дней в формате iCalendar (`.ics`) для импорта в личный календарь;
- организатор может добавить свободный комментарий с деталями; партнёр получит письмо и обновлённый `.ics` с тем же идентификатором события;
- адаптивный русскоязычный PWA-интерфейс.

## Реальные письма через Unisender Go

В Unisender Go перейдите в «Настройки → Домены отправки» и добавьте домен, которым вы владеете. В форме укажите домен отправителя и поддомен для трекинга, например `link.example.com`. Сервис покажет DNS-записи: добавьте их у регистратора домена в точности как указано, затем нажмите «Проверить» и дождитесь зелёных статусов. Обычно это TXT-записи подтверждения, DKIM и SPF, а также NS-записи для поддомена трекинга. Не создавайте вторую SPF-запись: если она уже есть, добавьте в неё `include:spf.unisender.ru` по инструкции сервиса.

После подтверждения создайте API-ключ в Unisender Go и добавьте его в `.env` сервера:

```env
MAIL_FROM=Date, not Hate <ваш-подтверждённый-email@example.com>
UNISENDER_GO_API_KEY=ваш-api-ключ
```

Все письма — подтверждение email, magic-link, приглашения, уведомления и `.ics`-вложения — отправляются через HTTPS API Unisender Go. Переменные `SMTP_*` и `BREVO_API_KEY` больше не используются: удалите их из своего `.env`.

Приложение отключает отслеживание прочтений и переходов: для личных приглашений оно не требуется. Если Unisender Go всё равно вернёт ошибку `229`, напишите в его поддержку с просьбой разрешить отключение `track_links` и `track_read` для проекта.
